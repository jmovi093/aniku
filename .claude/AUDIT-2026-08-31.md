# Auditoría de limpieza — 2026-08-31

Barrido completo del proyecto post-migración a anidb: archivos huérfanos,
fragmentos de la API vieja en código activo, y funcionalidad rota por la
migración. Verificado archivo por archivo con grep antes de tocar nada — no
se confió en el sondeo inicial sin comprobar cada hallazgo.

Los 4 servicios de AllAnime (`AnimeService.js`, `CatalogService.js`,
`ScheduleService.js`, `AnimeDetailsService.js`) y sus dependencias directas
(`VideoService.js`, `utils/apiConfig.js`, `utils/urlDecoder.js`) **se dejan
intactos a propósito** como referencia — ver `.claude/ANIDB-SOURCE.md`.

## 🐛 Bugs reales corregidos (no solo limpieza)

### 1. `useWatchingNavigation.js` — crash por `Alert` sin importar
Línea 91 llamaba a `Alert.alert(...)` pero el archivo solo importaba
`CustomAlert`. Se disparaba cuando "continuar viendo" encontraba el episodio
pero sin providers disponibles → `ReferenceError: Alert is not defined`.
**Fix**: agregado `import { Alert } from "react-native"`.

### 2. "Continuar viendo" y el pre-fetch usaban el pipeline VIEJO desconectado
`VideoStreamService.js` importaba **directo** `./AnimeService` (el AllAnime
viejo), no el adaptador `services/source`. Dos flujos activos lo llamaban:
- `useWatchingNavigation.js` → `continueWatching()`: con un `animeId` de
  anidb, la llamada al pipeline de AllAnime fallaba siempre en silencio
  (`.catch(() => null)`), así que "seguir viendo" **nunca reproducía
  directo** y terminaba siempre en el fallback de navegar a la lista de
  episodios.
- `useEpisodeManager.js` → pre-fetch del siguiente episodio: el mismo fallo
  silencioso hacía que la "optimización" nunca calentara nada de verdad.

**Fix**: ambos ahora llaman `AnimeSource.getOptimizedVideoLinks(...)` (el
adaptador activo). `VideoStreamService.js` quedó sin ningún importador →
**borrado**.

### 3. `Referer: "https://allmanga.to"` hardcodeado en reproducción y descargas
`VideoPlayer.js` (2 lugares: fuente nativa y proxy de Chromecast) y
`DownloadService.enqueueEpisode` mandaban ese header a **cualquier** URL,
incluidas las de `hls.anidb.app` — un dominio ajeno al CDN actual.
Verificado en vivo que `hls.anidb.app` no exige ningún `Referer` (200/206 en
6 combinaciones de headers probadas). **Fix**: el header solo se manda si el
link trae `requiresReferer: true` explícito (el caso AllAnime, por si esa
fuente se reconecta); por default ya no se manda nada.

### 4. Llamada muerta a `VideoService.clearJsonCache()`
En el cleanup de `useAnimeDetailsEpisodes.js`, limpiaba una caché que nunca
se llena porque la lógica real de `VideoService.js` no se ejecuta desde el
flujo activo de anidb. Import y llamada eliminados.

## Riesgos conocidos, no tocados en esta pasada

- `resolveNextEpisode()` en `useWatchingNavigation.js` calcula el siguiente
  episodio como `current + 1` (numérico). Funciona para numeración contigua
  (incluida la de anidb que continúa entre temporadas, ej. Slime S2 25→26),
  pero **no** para especiales decimales (`2` → `2.5`) — a diferencia de
  `useEpisodeManager.js`, que ya usa la lista real. No se tocó porque cambiar
  el flujo (que hoy pide la lista en paralelo con los links, no antes)
  requiere reordenar la función y no hay caso reportado que lo necesite.
- `HistoryService.getWatching()` (solo local) vs `HybridHistoryService`
  (local+nube) conviven en distintos puntos de la feature Watching — no se
  investigó si hay una ventana real de inconsistencia tras reinstalar.
